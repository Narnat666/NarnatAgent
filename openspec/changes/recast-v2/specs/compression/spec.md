# Spec Delta

## Purpose

定义上下文压缩能力的行为契约：窗口占比与触发判定、摘要请求构造、保留尾部切点选择、压缩后会话重建、结果归因、溢出恢复、手动压缩（/compact）与 token 估算口径。压缩全程在内存中完成、不留中间文件，且摘要成功前不改动历史；对历史的整体更新经由 messages 能力的受控替换接口一次性生效。

## ADDED Requirements

### Requirement: 窗口占比与触发判定

系统 SHALL 以「最近一次服务端返回的输入 token 数 ÷ 配置的上下文窗口大小 × 100」计算窗口占比；窗口大小 ≤ 0 或输入 token ≤ 0 时占比视为无数据（不告警、不压缩）。在用户轮边界：占比 ≥ 压缩阈值（默认 95%，闭区间比较）时 SHALL 先压缩再请求。每次轮次结束后 SHALL 依据最新占比检查告警：占比 ≥ 告警阈值（默认 50%）时输出一次 `窗口占比已达{N}%，建议开启新对话`（N 为告警阈值数字），本会话仅一次；压缩成功后占比数据与告警状态 SHALL 一并重置（此后可再次告警）。

#### Scenario: 达到压缩阈值先压缩
- **WHEN** 用户提交输入时占比 ≥ 压缩阈值
- **THEN** 先执行压缩；成功时该输入随压缩重建一并写入历史（不重复追加），随后进入正常请求

#### Scenario: 未达阈值直接请求
- **WHEN** 用户提交输入时占比低于压缩阈值
- **THEN** 不压缩，直接追加用户输入并进入正常请求

#### Scenario: 压缩失败仍保留用户输入
- **WHEN** 触发压缩但压缩失败或被中断
- **THEN** 用户输入仍写入历史，本轮不产生 AI 回复，回到输入等待

#### Scenario: 告警仅一次
- **WHEN** 占比首次达到告警阈值
- **THEN** 输出告警文案一次；同一会话内不再输出，直到压缩成功重置

#### Scenario: 窗口无效
- **WHEN** 配置的窗口大小 ≤ 0，或尚未收到 token 数据
- **THEN** 占比无数据，不告警也不压缩

### Requirement: 运行中主动压缩

系统 SHALL 在工具轮次收到 token 用量时刷新窗口占比；每次请求发出前自查，占比 ≥ 压缩阈值时先压缩（不携带新用户输入，压缩后以内部继续指令收尾）再发请求。压缩期间 SHALL 有可见提示，压缩成功与失败都 SHALL 继续本次请求（失败即维持现状照常请求）。

#### Scenario: 自我运行期间超阈值
- **WHEN** AI 连续工具轮次后占比升至压缩阈值以上
- **THEN** 下一次请求前先压缩历史，成功提示后继续任务；失败提示后照常请求

#### Scenario: 未超阈值不压缩
- **WHEN** 请求前占比低于压缩阈值
- **THEN** 不做任何压缩，直接发请求

### Requirement: 摘要请求构造

压缩 SHALL 以「全部历史消息 + 末尾一条 `user` 角色的压缩指令」作为摘要请求，并禁用工具定义。压缩指令 SHALL 为结构化检查点模板：固定小节顺序（原始请求与意图、关键技术概念、文件与代码、错误与修复、待办任务、当前工作、下一步、关键上下文），空节写 `(无)` 且不得省略任何一节；要求只输出检查点文本、不提及摘要请求与压缩本身、不与历史中已有摘要原文照抄叠加，并在已有 `# 上一轮对话成果` 摘要时合并为单一整合摘要。摘要正文 SHALL 只收集正常文本增量（正文块），带工具调用字段的块不计入。

#### Scenario: 请求内容
- **WHEN** 触发压缩
- **THEN** 摘要请求 = 全部历史 + 末尾压缩指令（`user` 角色），且不携带任何工具定义

#### Scenario: 压缩请求自身超限
- **WHEN** 摘要请求因上下文超限被服务端拒绝（完成原因为上下文超限）
- **THEN** 该次压缩归因为「压缩请求超限」，提示"压缩请求自身超出模型上下文限制"，不与「总结为空」混淆

### Requirement: 保留尾部切点选择

压缩 SHALL 尊重配置的保留尾部预算（默认 16000 token；显式 0 或负值 = 不保留、全量压缩）：从尾部向前按启发式估价累计至预算得到候选切点，再向前回退，使保留尾部首条必须是 `user` 消息（满足严格后端的角色交替要求，同时保证工具调用与其结果配对不被拆散）；保留区 SHALL 只含非 system 消息（system 消息不进保留区，由新的系统提示词与摘要承担）。预算覆盖全部对话且切点合法时 SHALL 保留全部对话消息；全部为 system 消息、预算覆盖全部对话但对话区首条不是 user、或预算无效时，SHALL 回退为全量压缩（不保留尾部）。

#### Scenario: 预算为 0 全量压缩
- **WHEN** 保留尾部预算为 0
- **THEN** 压缩后不保留任何尾部消息，仅剩系统提示词与摘要

#### Scenario: 切点回退不拆散工具对
- **WHEN** 按预算选出的候选切点落在 assistant（含工具调用）或 tool 消息上
- **THEN** 切点向前回退到最近的 user 消息，工具调用与其结果同在保留区或被一并摘要

#### Scenario: system 消息不进保留区
- **WHEN** 历史中存在 system 消息（含中段注入）且切点临其附近
- **THEN** 保留区不含任何 system 消息

#### Scenario: 无安全切点时全量压缩
- **WHEN** 对话区首条不是 user 消息（异常序列）
- **THEN** 放弃保留，执行全量压缩

### Requirement: 压缩后会话重建

压缩成功 SHALL 以「系统提示词 + 摘要 + 保留尾部」重建会话：首条为 `system`（当前系统提示词）；摘要以独立 `system` 消息承载，标题固定为 `# 上一轮对话成果`；其后依次是保留尾部中非 system 的消息。重建 SHALL 以一次性整体替换生效，失败或中断时历史保持原样。自动与溢出恢复路径重建后 SHALL 以 `user` 收尾：保留尾部末条已是 `user` 时，新输入以空行拼接合并进该条（避免连续 user）；否则追加一条新的用户消息。手动压缩不携带输入：保留尾部末条为 `user` 时，该条及其之前连续的 `user` 消息 SHALL 整段剔除（内容已进摘要），剔除条数与估算 token SHALL 计入替换统计。

#### Scenario: 重建结构
- **WHEN** 压缩成功
- **THEN** 新会话 = `system`(系统提示词) + `system`(`# 上一轮对话成果\n\n`摘要) + 保留尾部非 system 消息

#### Scenario: 尾部末条为 user 时合并新输入
- **WHEN** 自动压缩且保留尾部末条是 user 消息
- **THEN** 新输入以空行拼接进该条，不出现连续两条 user

#### Scenario: 尾部非 user 时追加输入
- **WHEN** 自动压缩且保留尾部末条不是 user（或未保留尾部）
- **THEN** 追加一条内容为本次输入的 user 消息

#### Scenario: 手动压缩剔除尾部连续 user
- **WHEN** 手动压缩且保留尾部末条是 user 消息
- **THEN** 从尾部向前的连续 user 消息整段剔除，并计入替换统计

#### Scenario: 尾部含 system 被丢弃
- **WHEN** 保留尾部中（非首位）出现 system 消息
- **THEN** 重建时该消息被静默丢弃，不进入新会话

### Requirement: 结果归因与历史不变性

压缩结果 SHALL 报告成功与否、被替换的对话消息条数与估算 token 数（统计口径，供提示展示），失败时给出归因，取值集合固定为：无历史可压缩（empty）、用户中断（interrupted）、摘要请求出错（llm_error）、总结为空（empty_summary）、压缩请求超限（overflow）。失败与中断路径 SHALL 不改动历史（仅成功路径执行重建替换）。归因规则：仅手动路径在「对话区为空或保留预算覆盖全部对话」时提前拒绝为「无历史可压缩」（不发起摘要请求）；「用户中断」覆盖请求前已取消、摘要流中被取消、零输出且已取消三种情形（避免误归因为「总结为空」）；「摘要请求出错」对应模型返回错误完成标记；「总结为空」对应摘要去除空白后为空。

#### Scenario: 无历史可压缩（手动路径）
- **WHEN** 手动压缩但保留预算覆盖全部对话（或对话区为空）
- **THEN** 不发起摘要请求，直接归因「无历史可压缩」

#### Scenario: 零输出且已取消
- **WHEN** 摘要流没有任何输出且用户已取消
- **THEN** 归因「用户中断」，而非「总结为空」

#### Scenario: 摘要请求出错
- **WHEN** 摘要流返回错误完成标记
- **THEN** 归因「摘要请求出错」，提示"LLM调用出错"，历史不变

#### Scenario: 失败不改动历史
- **WHEN** 压缩以任一种失败或中断归因结束
- **THEN** 消息序列与压缩前逐字一致

### Requirement: 溢出恢复

正常请求被服务端以上下文超限拒绝时（完成原因为上下文超限），系统 SHALL 执行一次溢出恢复：此时本轮 assistant 尚未写入历史，压缩后可原地重发请求（幂等安全）；压缩重建以内部继续指令收尾（告知历史已压缩、基于当前上下文直接继续推进任务、无需复述历史），重发前 SHALL 给出用户可见提示。每次运行 SHALL 最多恢复一次：第二次超限、压缩恢复失败、或未配置压缩能力时，SHALL 提示"请求超出模型上下文限制，请尝试缩减本次输入或保存会话后开启新对话"并正常收尾。

#### Scenario: 首次超限自动压缩重发
- **WHEN** 请求被判定为上下文超限且本次运行尚未恢复过
- **THEN** 压缩历史（无新输入、以内部继续指令收尾），成功提示后原地重发请求

#### Scenario: 二次超限不再恢复
- **WHEN** 重发后再次被上下文超限拒绝
- **THEN** 不再压缩，提示缩减输入或开启新对话并收尾

#### Scenario: 恢复失败
- **WHEN** 溢出恢复的压缩失败
- **THEN** 提示"自动压缩失败，请求仍超出模型上下文限制…"并收尾

### Requirement: 手动压缩

`/compact` 命令 SHALL 触发手动压缩：不受窗口占比阈值限制、不携带用户输入、不追加任何对话消息；压缩期间允许取消（与运行中压缩的取消手感一致），无论成功、失败或异常，结束后必须恢复为输入等待状态。结果 SHALL 返回状态与用户文案：成功 → `已压缩 {N} 条历史消息（约 {M} tokens）` 并重置占比与告警，且由会话层修正会话基准并落盘；无历史可压缩 → `没有可压缩的历史对话`；被取消 → `压缩已取消，历史未变更`；摘要请求出错、总结为空、压缩请求超限 → 对应「…，历史未变更」提示；未知原因 → `压缩失败: 未识别的失败原因`。失败与取消 SHALL 不改动占比与历史。

#### Scenario: 成功
- **WHEN** 手动压缩成功替换 N 条、约 M tokens
- **THEN** 提示 `已压缩 {N} 条历史消息（约 {M} tokens）`，随后会话内容被保存落盘

#### Scenario: 取消
- **WHEN** 手动压缩过程中用户按 Esc 取消
- **THEN** 提示 `压缩已取消，历史未变更`，恢复输入等待

#### Scenario: 无可压缩历史
- **WHEN** 保留预算已覆盖全部对话（或对话区为空）
- **THEN** 提示 `没有可压缩的历史对话`

### Requirement: token 估算口径

系统 SHALL 以启发式估算消息 token 数：CJK 字符（含全角符号、假名、谚文）约 0.7 token/字，其余字符约 0.25 token/字符，结果向上取整；每条消息附加固定 8 token 框架开销；计入 `content`（字符串或块列表文本）、`thinking`、`tool_calls` 的函数名与参数。估算 SHALL 仅用于切点选择与结果统计展示；精确的窗口压力判断以服务端返回的输入 token 为准。

#### Scenario: 中英文估价
- **WHEN** 分别估算等长的纯中文文本与纯英文文本
- **THEN** 中文按约 0.7/字、英文按约 0.25/字符的系数计算后向上取整

#### Scenario: 消息级汇总
- **WHEN** 估算一条带思考与工具调用的 assistant 消息
- **THEN** 总估值 = 8 + 正文估值 + 思考估值 + 各工具调用（名称与参数）估值

### Requirement: 兼容性怪癖保持

以下现存边缘行为 SHALL 在重构中保持等价（避免用户可感知差异）：压缩阈值比较为闭区间（恰等于阈值即触发）；自动与溢出路径在压缩失败后的占比处理为——被中断 → 占比与告警重置、摘要请求出错 → 占比置为「压缩阈值 − 10」（下限 0）以延后重试；手动路径除成功外均不动占比；自动路径不做「无历史可压缩」提前拒绝（即使保留预算覆盖全部对话仍走完整流程，重建照常把触发输入写入历史）；溢出恢复的内部继续指令以字面 `[]` 开头；摘要标题字面量 `# 上一轮对话成果` 与压缩指令中的旧摘要识别规则配套，不得单侧改动。

#### Scenario: 恰等于阈值即触发（兼容怪癖）
- **WHEN** 窗口占比恰等于压缩阈值
- **THEN** 判定为需要压缩

#### Scenario: 失败后的占比处理（兼容怪癖）
- **WHEN** 自动压缩或溢出恢复压缩因摘要请求出错而失败
- **THEN** 占比被置为「压缩阈值 − 10」，即阈值以下的固定值，后续可再次触发
