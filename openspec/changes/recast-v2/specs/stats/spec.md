# Spec Delta

## Purpose

定义统计与费用能力的行为契约：用量累计口径（输入/输出/缓存命中 token 与缓存命中率）、费用计算（按用户配置的定价表逐项计算）、成本日志 CSV 的写入与容量轮转、余额查询（开关、认证方式、响应取值）与查询节奏，以及统计栏数据的供给口径（显示条件与样式归属终端输出与界面能力）。成本日志文件格式与费用口径是已发布契约，必须跨版本兼容。

## ADDED Requirements

### Requirement: 用量累计口径

系统 SHALL 在每轮 LLM 请求返回后按用量数据（输入 token、输出 token、缓存命中 token）更新统计：输出 token 全程累加；输入 token 为最近一轮的值（当前上下文快照）；同时维护全程累计输入与累计缓存命中，用于 token 加权缓存命中率。对外读数口径：输入 token = 最近一轮输入；输出 token = 全程累计输出；缓存命中率 = 累计缓存命中 / 累计输入（分母为 0 时取 0.0）；费用 = 全程累计费用。

#### Scenario: 多轮累计
- **WHEN** 连续两轮分别返回输入 100/输出 10 与输入 500/输出 20
- **THEN** 输入读数为 500（最近一轮），输出读数为 30（累计）

#### Scenario: 缓存命中率加权
- **WHEN** 两轮输入 100 与 500、缓存命中 50 与 100
- **THEN** 命中率 = 150 / 600 = 0.25（按 token 加权，而非两轮简单平均）

#### Scenario: 无数据时命中率
- **WHEN** 尚无任何用量数据
- **THEN** 缓存命中率为 0.0

### Requirement: 费用计算（定价表）

费用 SHALL 仅按用户配置的定价表计算（每百万 token 单价，模型名为键，分项为输入、缓存命中、输出）：本轮费用 = (输入 − 缓存命中) × 输入单价 / 1e6 + 缓存命中 × 缓存单价 / 1e6 + 输出 × 输出单价 / 1e6。未配置定价的模型 SHALL 计为 0 费用。累计费用为各轮相加，且不因运行中切换模型而重算。

#### Scenario: 按定价计算
- **WHEN** 定价为输入 2、缓存命中 0.5、输出 8（元每百万 token），一轮输入 100000、缓存命中 40000、输出 20000
- **THEN** 本轮费用 = (60000×2 + 40000×0.5 + 20000×8) / 1e6 = 0.3 元

#### Scenario: 未配置定价
- **WHEN** 所用模型不在定价表内
- **THEN** 本轮与累计费用均不增加（按 0 计算）

### Requirement: 成本日志写入

配置「费用日志.启用」开启时，系统 SHALL 在每次 LLM 请求后向 CSV 追加一行（默认输出文件 `.narnat/data/cost_log.csv`，配置「费用日志.输出文件」非空时以配置为准），列依次为：时间（本地时区 `YYYY-MM-DD HH:MM:SS`）、模型、输入tokens、缓存命中tokens、缓存未命中tokens（= 输入 − 缓存命中）、输出tokens(含思考)、输入费用(元)、缓存费用(元)、输出费用(元)、本次费用(元)、累计费用(元)；费用数值保留 9 位小数。新文件（大小为 0）SHALL 先写表头；文件以 UTF-8-sig 编码（含 BOM）追加写。写入失败（OSError，如文件被办公软件独占）SHALL 不丢行：失败行进入内存队列，下次写入前先补写积压行、成功一行出队一行、失败即停。

#### Scenario: 首次写入含表头
- **WHEN** 启用费用日志后的第一次请求完成
- **THEN** 目标文件写入表头行与 11 列数据行

#### Scenario: 未命中列口径
- **WHEN** 某轮输入 1000、缓存命中 300
- **THEN** 「缓存未命中tokens」列为 700

#### Scenario: 写失败补写
- **WHEN** 某次写入抛出 OSError（文件被独占）
- **THEN** 该行进入队列；下一次写入前先补写积压行再写当前行，不丢行不重复写

#### Scenario: 未启用不写
- **WHEN** 「费用日志.启用」为关闭
- **THEN** 不进行任何日志写入

### Requirement: 成本日志容量与轮转

「费用日志.最大容量MB」SHALL 控制活动文件容量（按配置换算为字节；负值按 0 处理=不轮转）。写入前若活动文件大小已达上限且上限大于 0，SHALL 执行双文件轮转：删除旧的 `<主名>_bak<扩展名>` 备份，把当前写满文件改名为备份，新活动文件从表头开始写；磁盘上 SHALL 始终只保留 1 个活动文件 + 1 个备份文件。轮转失败（文件被独占）SHALL 不中断写入：本次不写表头、继续追加到已超限的活动文件（尽力而为）。

#### Scenario: 达到上限触发轮转
- **WHEN** 活动文件大小达到上限且有新行待写
- **THEN** 旧备份被替换、当前文件改名为 `<主名>_bak.csv`，新活动文件先写表头再写该行

#### Scenario: 上限为 0 不轮转
- **WHEN** 容量上限为 0（或负值按 0 处理）
- **THEN** 永不轮转，持续追加同一活动文件

#### Scenario: 轮转失败降级
- **WHEN** 轮转改名失败（文件被独占）
- **THEN** 不写表头、继续向原文件追加，该行不丢失

### Requirement: 余额查询

余额查询 SHALL 由配置驱动：仅当「余额查询.启用」开启且「查询地址」非空时发起。请求 SHALL 按「认证方式」构造：`bearer`（默认）为 `Authorization: Bearer <接口密钥>`，`x-api-key` 为 `x-api-key: <接口密钥>`；HTTP GET、超时 8 秒。响应非 200、JSON 解析失败、按「响应路径」取不到值（点号分隔的 JSONPath，支持数字数组索引，如 `balance_infos.0.total_balance`）、数值转换失败等任何异常 SHALL 静默处理为「无结果」，不输出错误。「货币路径」同样解析、命中时随结果返回。

#### Scenario: bearer 认证取值
- **WHEN** 认证方式为 bearer 且响应路径命中数值
- **THEN** 请求携带 Bearer 头，返回该余额值（货币路径命中时附货币）

#### Scenario: x-api-key 认证
- **WHEN** 认证方式为 x-api-key
- **THEN** 请求以 x-api-key 头携带密钥

#### Scenario: 失败静默
- **WHEN** 响应非 200、JSON 解析失败或路径取值失败
- **THEN** 本次查询视为失败、无任何错误输出

#### Scenario: 未启用不查询
- **WHEN** 查询开关关闭或查询地址为空
- **THEN** 不发起任何网络请求，结果为空

### Requirement: 余额查询节奏

余额查询 SHALL 按轮次间隔执行（每 10 轮一次）：仅当轮次号为间隔的整数倍且接口密钥非空时发起查询；查询成功时以其结果更新显示余额，查询失败时保持上次显示值；其余情形（非整数倍或密钥为空）显示余额重置为 0.0。

#### Scenario: 整除轮查询
- **WHEN** 轮次号为 10 的倍数且密钥非空
- **THEN** 发起余额查询；成功时刷新显示余额

#### Scenario: 非整除轮清零
- **WHEN** 轮次号不是间隔的整数倍（或密钥为空）
- **THEN** 显示余额置 0.0

#### Scenario: 查询失败保持上次值
- **WHEN** 整除轮查询失败（网络或解析异常）
- **THEN** 显示余额保持上次成功查询的值

### Requirement: 统计栏数据供给

本能力 SHALL 仅提供统计数据的口径，统计栏的显示开关、格式与着色归属终端输出与界面能力：输入 token（最近一轮）、输出 token（全程累计）、缓存命中率（0~1 的比例值）、费用（全程累计，人民币元）、余额（最近一次成功查询的值）。输入 token SHALL 同时作为自动保存门槛与上下文占比的读数来源。

#### Scenario: 统计栏读数
- **WHEN** 界面请求统计数据
- **THEN** 返回上述口径的输入 token、输出 token、缓存命中率、费用、余额五项

### Requirement: 兼容性怪癖保持

以下现存边缘行为 SHALL 在重构中保持等价（避免用户可感知差异）：显示余额 0.0 同时表示「未到查询轮」与「余额为 0」，界面无法区分；缓存命中大于输入时「缓存未命中tokens」为负值且不做钳制；定价表缺分项键（输入/缓存命中/输出）时抛错传播到统计更新调用（不静默兜底）；费用日志的失败行仅驻留内存、且只在下次请求时补写（此后无请求则永久驻留）；用量数据缺输入/输出 token 键时抛错（不做防御性取值）；运行中切换模型后已累计费用不重算。若未来修正，须作为独立变更处理。

#### Scenario: 余额 0.0 双关（兼容怪癖）
- **WHEN** 显示余额为 0.0
- **THEN** 无法区分「未查询」与「余额为 0」（现状保持）

#### Scenario: 负数未命中（兼容怪癖）
- **WHEN** 某轮缓存命中 token 大于输入 token
- **THEN** 费用日志的「缓存未命中tokens」列为负数（现状保持）

#### Scenario: 定价缺键抛错（兼容怪癖）
- **WHEN** 定价表缺少分项键
- **THEN** 错误从统计更新路径抛出（现状保持）
