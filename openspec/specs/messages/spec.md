# messages Specification

## Purpose
定义消息存储能力的行为契约：对话历史的数据结构与角色语义、只读视图、受控修改与原子替换、中断补齐与请求前的序列修复。本能力是对话历史（messages）的唯一所有者——外部只能经只读视图读取、经受控接口修改；消息字典的字段名与角色取值是对外数据契约，磁盘会话文件、模型请求构造与压缩重建均以其为准，必须跨版本兼容。

## Requirements

### Requirement: 消息序列与角色契约

系统 SHALL 以唯一列表持有对话历史，创建时即以一条 `system` 消息（系统提示词）开头；此后按发生顺序追加 `user`（用户输入或系统提醒）、`assistant`（模型回复）与 `tool`（工具结果）消息。消息 SHALL 为字典：`system`/`user` 含 `content` 字符串；`assistant` 含 `content` 与可选的 `tool_calls`、`thinking`、`thinking_signature`；`tool` 含 `tool_call_id` 与 `content`。

#### Scenario: 构建即含 system 首条
- **WHEN** 以系统提示词构建消息列表
- **THEN** 列表恰含一条 `{"role": "system", "content": <系统提示词>}`
- **AND** 后续追加的消息依次排在其后

#### Scenario: assistant 可选字段写入规则
- **WHEN** 追加一条 assistant 消息
- **THEN** `content` 为空串或缺失时记为 `null`（非空原样保留）；`thinking` 仅在显式给出时写入该字段（空串是合法值），未给出则不出现该字段；`thinking_signature` 仅在显式给出时写入该字段；`tool_calls` 仅非空时写入该字段

#### Scenario: tool 消息结构
- **WHEN** 回填某次工具调用的结果
- **THEN** 追加 `{"role": "tool", "tool_call_id": <调用 id>, "content": <结果文本>}`

### Requirement: 只读视图

系统 SHALL 对外只提供只读视图：视图不暴露内部列表本身，外部无法增删改列表结构；读取支持长度、下标（含负下标，-1 为末条）与迭代。视图为实时视图——内部消息变化对视图立即可见；导出列表 SHALL 返回浅拷贝（外部增删导出列表不影响内部结构）。

#### Scenario: 外部拿不到内部列表引用
- **WHEN** 调用方获取视图或导出列表并尝试增删其中元素
- **THEN** 内部消息序列结构不受影响

#### Scenario: 实时可见
- **WHEN** 已持有视图后又向历史追加了消息
- **THEN** 该视图的长度与末条内容反映追加后的结果

### Requirement: 受控修改接口

系统 SHALL 以受控接口作为历史的唯一修改入口：追加 `system`（技能注入等）、追加 `user`、追加 `assistant`、追加 `tool` 结果、批量补齐中断结果，以及以完整新列表一次性原子替换全部消息。压缩重建对历史的整体更新即经此替换接口生效（压缩编排见 compression 能力）。

#### Scenario: 追加 system 消息（技能注入）
- **WHEN** 注入技能内容
- **THEN** 以新的 `system` 消息追加在序列中，首条系统提示词不被覆盖

#### Scenario: 原子替换
- **WHEN** 以一份完整新列表替换全部消息（如压缩重建）
- **THEN** 旧消息整体消失、新列表整体生效，替换后读取到的即为新内容

### Requirement: 中断补齐

系统 SHALL 在工具执行被用户中断时，对本轮工具调用逐项补齐：已有真实结果（已完成）的调用不动，未完成的每一项按原顺序在序列末尾追加一条内容为 `[用户中断]` 的 `tool` 消息。

#### Scenario: 部分完成时补齐
- **WHEN** 本轮 3 个工具调用中仅第 1 个已完成时用户中断
- **THEN** 追加两条 `[用户中断]` 工具消息，`tool_call_id` 依次为第 2、3 个调用

#### Scenario: 全部完成时不补齐
- **WHEN** 中断发生时本轮所有工具调用均已完成
- **THEN** 不追加任何补齐消息

### Requirement: 请求前序列修复

系统 SHALL 在发出请求前修复被中断留下的不完整序列：以全部已有 `tool` 消息的非空 `tool_call_id` 组成已回复集合；遍历 assistant 消息的 `tool_calls`，为不在集合中的调用按序在序列末尾追加 `[用户中断]` 工具消息（同一 id 只补一次）。若本次修复确实追加过，且修复后序列末条为 `tool`，SHALL 再追加一条合成 assistant 消息：`content` 与 `thinking` 为同一非空占位文本 `（用户中断了工具执行）`，且无工具调用字段（思考模式下请求尾部的 assistant 必须携带非空思考块）。未发生第一步修复时，SHALL 不追加该合成消息。

#### Scenario: 未回复的工具调用被补齐
- **WHEN** 历史中存在 assistant 工具调用但缺少对应工具结果
- **THEN** 按调用顺序在序列末尾补充 `[用户中断]` 工具消息，序列不再悬空

#### Scenario: 修复后尾部为工具则合成 assistant
- **WHEN** 修复追加了工具消息且序列末条是 `tool`
- **THEN** 追加合成 assistant：正文与思考均为 `（用户中断了工具执行）`

#### Scenario: 未修复时不追加合成 assistant
- **WHEN** 序列无缺失工具结果，仅末条恰为 `tool`
- **THEN** 不做任何追加

#### Scenario: 重复 id 只补一次
- **WHEN** 同一工具调用 id 在多条 assistant 消息中出现且均未回复
- **THEN** 该 id 只补一条 `[用户中断]` 工具消息

### Requirement: 兼容性怪癖保持

以下现存边缘行为 SHALL 在重构中保持等价（避免用户可感知差异）：视图与导出列表中的消息字典与内部共享（可改写字段内容，除列表结构外无隔离）；整体替换接受任意长度（含清空，无最小长度保护）；序列修复只处理「缺失工具结果」与「修复后尾部为工具」两种形态，不处理顺序错乱或工具消息无对应 assistant 等其它异常；序列修复对缺 id 的工具调用项跳过，而中断补齐直接读取 id（缺 id 即异常）；合成占位文本 `（用户中断了工具执行）` 是跨模块判定依据（思考回传开关开启时按其字面量决定是否回传），禁止改动其文本。

#### Scenario: 消息字典共享（兼容怪癖）
- **WHEN** 调用方经视图取出消息字典并修改其 `content`
- **THEN** 内部消息随之改变（现状保持）

#### Scenario: 整体替换允许清空（兼容怪癖）
- **WHEN** 以空列表执行整体替换
- **THEN** 序列被清空，系统不补回 system 首条、不做任何保护
