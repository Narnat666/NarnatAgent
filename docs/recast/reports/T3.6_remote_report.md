## 2. 结构改进（design D7）

### 2.1 六组重复函数合并：旧代码组 → 新实现单点

| # | 组 | 旧实现位置 | 新实现单点 | 两族差异的显式参数化 |
|---|---|---|---|---|
| 1 | 会话注册表（分配/回收/占位/清理） | `terminal/__init__.py:245-260` `_allocate_session_id`、`:714-719` `cleanup`；`serial/__init__.py:537-553` `_allocate_session_id`、`:526-534` `cleanup` | `common.SessionSlots.allocate` / `allocate_locked` / `reserve` / `drop_reserved` / `cleanup` | `is_dead` 谓词（Terminal：`is_closed()`；Serial：`not is_alive`）；占位槽（Serial 连接中置 `None`）在同一算法内"不可抢占" |
| 2 | 会话解析 | `terminal/__init__.py:362-412`、`serial/__init__.py:556-599` | `common.resolve_explicit_slot` / `resolve_auto_slot` / `match_slots` | 文案由各族的消息回调给出；键匹配留在各族（devN + IP 宽松引用 vs 端口名匹配），锁内快照 + 锁外构造文案 |
| 3 | status | `terminal/__init__.py:659-674`、`serial/__init__.py:464-482` | `common.slot_state_label`（状态段）+ `SessionSlots.free_count`（空闲计数） | 行格式各族显式（`devN(终端M)` + 目录 vs `终端N` + `port @baudrate`） |
| 4 | close | `terminal/__init__.py:677-711`、`serial/__init__.py:485-523` | `common.close_sessions` | `key_flow` 回调（devN/越界/非法判定 vs 端口匹配）、`all_msg`/`sid_missing_msg`/`sid_done_msg`/`placeholder_msg` 文案回调、`clear_active`（Serial 清活跃集合） |
| 5 | cleanup | 见 #1 | 同 `SessionSlots.cleanup`（关全部 + 清注册表 + 清活跃标记与焦点引用） | 无差异（统一实现） |
| 6 | 删除确认 | `terminal/__init__.py:538-567`、`:609-634`（内联双份）；`serial/__init__.py:312-337` `_check_delete_safety` | `common.confirm_delete_command` | `extra_pattern`（Terminal 传 git 正则 `RE_GIT`；Serial 不传）；`tool_name`/`arguments` 由调用方组装 |

另有共用文本原语合并（旧 `ssh_session._ansi_sub` / `_clean_output` 行内 `\r` 合并 /
`serial_session._merge_cr_line` / `_clean_output` / 两族 `_truncate_output`）：

- `common.strip_ansi` + `common.ANSI_RE`（两族 ANSI 正则原本逐字相同）；
- `common.merge_cr_line`（行内 `\r` 覆盖合并）；
- `common.clean_output(crlf_is_newline, strip_markers)`——Serial 形态（CRLF 先归一、末尾整体
  `strip()`）与 Terminal 形态（`\r` 参与覆盖、仅去首尾空行与行尾空白、在空行压缩前删内部标记）
  的差异显式参数化；
- `common.truncate_middle(attach_tags)`——Terminal 形态（`safe_cut_points` 标签吸附 + `≈token`）
  与 Serial 形态（无标签吸附/无 token、字面量错误行）；`ssh_session.truncate_output` 与
  `serial_session.truncate_output` 成为薄包装。

### 2.3 常量统一与依赖注入

- **`AWAIT_CONFIRM`**：Terminal 侧旧字面量 `"__AWAIT_CONFIRM__"`（2 处）删除，与 Serial 统一引用
  `contracts.tool.AWAIT_CONFIRM`（对外值不变；registry 同时识别结构化字段与文本形态）。
- **`max_sessions` 构造注入**：`TerminalTool(max_sessions)` / `SerialTool(max_sessions)`，内部钳制
  1-10；替代旧 `TerminalRuntime.set_max_sessions` 类属性全局与 `SerialRuntime.max_sessions`
  硬编码。**明示修复项**：Serial 与 Terminal 接同一配置来源（默认 5 场景无差异）。
- 删除的死代码（D11 允许）：`SerialRuntime.set_max_sessions`（无调用者）；
  `terminal._close` 中不可达的 `close需要指定dev编号…` 兜底分支（未指定 host+session_id 已被
  "关闭全部"分支覆盖，零可观察行为差异）。

## 5. 发现的 spec 与旧实现偏差（按 D11 保持现状，建议独立变更裁决）

1. **`replace_all` 唯一性提示缺结尾 `]`**：spec 写作
   `[错误: 找到{N}处匹配，old_string不唯一。请扩大上下文使其唯一，或设置replace_all=True]`，
   旧实现（`remote.py:256-259`）该文案结尾**无 `]`**。按"对外契约冻结"保持旧实现（测试断言
   已按现状写并注明），未擅自补齐。
2. **用户拒绝确认的返回无框架标签**：spec「退出码与框架错误标签」称 Terminal 失败"一律使用
   带标签错误行"，但旧实现对用户拒绝返回 `[操作已取消: 此命令需用户确认]`（无标签，UI 不显示
   失败——用户选择而非框架失败）。保持旧实现（两族一致）。
