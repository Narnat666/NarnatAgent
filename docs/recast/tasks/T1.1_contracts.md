## 逐文件要求

### llm_events.py（TypedDict 集中定义，保持 dict 形态契约）

必须定义（命名可按惯例微调，语义不得变）：
- `Usage`：`prompt_tokens:int / completion_tokens:int / cached_tokens:int`
- 事件类型（TypedDict）覆盖 R1 报告 870-879 清单的全部形态：
  - 文本增量 `{"content": str}`
  - 工具就绪 `{"tool_calls": list[ToolCall], "finish_reason": str, "thinking": str|None, "thinking_signature"(可选)}`（Anthropic 有签名）
  - 完成（无工具）`{"finish_reason": str, "thinking": ...}`
  - 用量 `{"usage": Usage}`
  - 重试通知 `{"retry_notice": str}`
  - 流中断 `{"stream_interrupted": {"kind": "timeout"|"network"|"unknown", "detail": str}}`
  - 上下文超限 `{"finish_reason": "context_overflow"}`
  - 错误完成 `{"content": str, "finish_reason": "error"}`
- `ToolCall` 形状：`{"id": str, "type": "function", "function": {"name": str, "arguments": str}}`
- `LLMEvent` 联合类型 + 取值常量（`FINISH_REASONS`：stop/tool_calls/max_tokens/content_filter/server_busy/error/context_overflow；`INTERRUPT_KINDS`）
- 纯函数辅助谓词（无状态）：如 `is_text_delta(event)`（对应"含 content 且不含 tool_calls"判定）、`is_completion(event)`、`get_finish_reason(event)`、`get_tool_calls(event)`、`get_usage(event)` —— 谓词语义必须与 specs/llm 的消费规则一致

### tool.py

- `ToolDefinition`（dict 形状契约：`{"type":"function","function":{"name","description","parameters"}}`——保持 dict，这是 LLM API 契约）
- `ToolResult`：dataclass，字段：`llm_text: str`（给模型的文本，标签已剥离）、`ui_text: str|None = None`（UI 展示如着色 diff）、`await_confirm: bool = False`（挂起确认请求）
  - 另需承载"执行失败"标记（供调度层判定 UI 显示）：按 specs/tools-shell「退出码与框架错误标签」语义设计字段
- `Tool` Protocol：`name: str` / `definition() -> ToolDefinition` / `execute(args: dict, env: ToolEnv) -> ToolResult`
- 运行时状态协议（全部 Protocol，具体实现归各积木；字段/方法名可依 specs 微调）：
  - `ToolSettings`：只读配置面（ignore_dirs、max_output_chars、max_timeout_seconds、max_transfer_mb、git_skip_confirm、rm_skip_confirm、require_plan、min_tools、api_key 查询）
  - `PlanTracker`：当前计划（读写，TodoWrite 写、收尾提醒读）——方法如 `current()` / `replace(todos)`
  - `GoalState`：目标完成标记（置位/消费/复位）
  - `ReminderState`：软提醒标志（计划/后台各一，触发一次语义）
  - `DeleteGate`：删除确认挂起（暂存命令/取出/一次性"已确认"标记）
  - `ReadFileTracker`：已读文件集合（记录/查询）
  - `ToolEnv`：聚合门面——`settings` 属性 + 各 tracker 访问 + `confirm` 同步确认回调 + MCP 端口引用（`mcp` 行为按 specs/mcp 的 connect/disconnect 语义）
- `AWAIT_CONFIRM` 等跨模块字面量集中于此（消灭现状 "__AWAIT_CONFIRM__" 字面量双轨）

### output.py

- `TurnStats` dataclass：`input_tokens / output_tokens / cache_ratio / cost / balance / thinking_effort`（语义对齐 specs/ui 统计栏）
- `OutputSink` Protocol（对齐 specs/ui「流式输出会话句柄协议」与 design D4）：
  - `feed(text)`（内容增量，走 Markdown 渲染）
  - `notify(text)`（状态提示，纯文本提示行）
  - `finish(stats: TurnStats, with_stats: bool = True)`
  - `abort(message: str | None = None)`
  - `restart_attempt()`（重试重播：此前未完成内容作废、渲染缓冲清理——对应现状"流中断重试前的渲染重置"）
  - `cancelled: bool` / `aborted: bool`（属性）
- `InteractionPort` Protocol：
  - `begin_turn() -> OutputSink`
  - `read_confirmation(prompt: str) -> bool`
  - `notify_interrupted()`
  - （按 specs 需要补充，如动画/压缩提示的入口——对齐 specs/ui 动画章节的实际调用方需求）
- 方法名与语义以 specs/ui 为准；若 specs 未明说某方法，按"最小必要"设计并在 docstring 注明

### interrupt.py

- `InterruptSignal` Protocol：`is_set: bool` / `clear()` / `raise_()`；订阅能力 `subscribe(handler)`（handler 为无参回调，触发时同步调用）
- 双模式语义（运行/输入）的接口形态：按 specs/interrupt「运行/输入双模式状态机」设计（如 `enter_input_mode()` / `enter_run_mode()`）
- 具体实现（InterruptBus）归 `interrupt` 积木（不在本任务）

### 通用要求

- 全部文件：简体中文 docstring，注明"契约来源：specs/<x>"；类型标注完整；无 I/O、无状态、无三方依赖（只允许标准库 typing/dataclasses/enum/collections.abc）
- 辅助谓词必须纯函数（deterministic）
- `contracts` 是最底层（L0）：**禁止 import 新包其他积木**

### 测试要求（test_contracts.py）

- 每个 TypedDict 的样例构造（runtime 检查 dict 形态符合预期：如 `is_text_delta({"content": "x"})` 为真、`is_text_delta({"content": "x", "tool_calls": []})` 为假）
- 谓词边界：空 dict、未知键、finish_reason 取值
- 枚举常量与 R1 清单逐项一致（数量断言）
