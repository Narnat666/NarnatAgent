# T2.2b 修正任务：output 积木去除重复的配置归一化

## 背景（架构审计结论，务必先读）

T2.2 已交付的 `v2/narnat_agent/output/` 中，`style.py` 实现了一份"「界面」配置归一化"（中文键→英文、扁平键迁移、开关弹出等，函数如 `normalize`）。审计确认这是**重复实现**：

1. **旧实现的职责边界**：归一化在 `config/loader._build_ui_config` 内完成；`apply_style(ui_config)` 是**纯消费**——直接读标准英文分组（`colors`/`base_colors`/`codeblock`/…），不含任何中英键转换。
2. **基准的构造方式**同样表明纯消费：`v2/tests/baseline/data/output_style.json` 的 `apply_style` 用例直接喂 `{"colors": {...}}` 标准格式。
3. 两处归一化已出现**裁决分歧**（config 修正后为"英文键优先/直赋覆盖"；output 内为"中文优先/不覆盖"）——同层双轨，必须消除。

**决策：归一化唯一归属 config 积木**；output 的 `apply_style` 与相关内部逻辑改为纯消费标准化「界面」配置（对齐旧行为与基准）。

## 修改要求

1. `v2/narnat_agent/output/style.py`：
   - 删除重复的归一化函数（`normalize` 或实际名称）及其调用；`apply_style` 直接消费传入的标准化配置。
   - 保留的职责不变：色板注册、基础色角色解析、代码块背景、派生 token、配方解析、PTK 样式转换、DisplayState 开关写入、畸形配置静默容错、幂等重置语义。
   - 更新模块/函数 docstring：注明"输入契约为 config 归一化后的标准「界面」配置（见 specs/config 与 specs/output 的职责边界）"。
2. 不再处理中英键名——那属于 config 的测试面。
3. 若 `apply_style` 依赖"开关键回填"（`show_cost` 等 5 键）的行为，保持与旧实现一致（旧实现读传入 dict 的 `show_cost`/`show_balance`/`max_output_tokens`/`show_ratio`/`context_window`，缺省用默认值——以基准 `display_state` 组为准）。
4. `v2/tests/unit/test_output.py`：
   - 删除仅测试归一化的用例（约十余个），保留其余；
   - 若需要，补 2-3 个"apply_style 消费标准格式"的行为用例（含缺省开关行为）；
   - 与 `v2/tests/baseline/data/output_style.json` 的对照测试更新为直接喂标准格式。
5. 不得改动其他积木与文件。
