# T2.2 实施任务：output 积木（输出原语与颜色体系）

## 任务目标

重构 change `recast-v2` 的 Stage 1b：在 `v2/narnat_agent/` 实现 `output` 积木（终端输出原语、颜色体系、plain/quiet 模式、DisplayState）。

- **行为金标准**：`openspec/changes/recast-v2/specs/output/spec.md`（逐条对照，含兼容怪癖）
- **结构金标准**：`design.md`（D1/D7/D11）
- **现状参照**：`narnat_agent/output.py` + `docs/recast/reports/R6_report_ui.md`（output 部分）

## 交付物

- `v2/narnat_agent/output/__init__.py` — 聚合导出（保持旧包消费方所需的名与语义）
- 实现文件（建议 `console.py` / `colors.py` / `style.py`，可自行切分，但积木内聚）
- `v2/tests/unit/test_output.py` — 单元测试

## 实施要求

1. **行为面覆盖**（spec 为主）：颜色体系（色板+角色引用+配方解析+中文名替换与顺序怪癖）、plain/quiet 全局开关、Windows VT 启用、truecolor 检测降级、DisplayState 各显示开关数据流、`write`/`try_write` 语义（try 静默失败）、行首 `\r` 行为（plain 模式抑制）。
2. **结构改进**：消灭模块级可变全局（`_PLAIN`/`_QUIET_TOOLS`/`_COLORS` 这类）——以显式对象（如 `Console`/`DisplayState` 实例）承载；但**每处可观察行为不得变**（含"apply_style 后全局生效"的主题机制语义——新设计用实例注入达成同样效果，见 design D7）。
   - 注意：颜色实例被 ~20 个模块消费。新设计中"消费方获取颜色"的路径要显式（构造注入或模块级只读注册表——若选后者，模块级变量必须只写一次且经 allowlist 标注）。
3. **兼容怪癖**（spec 明列，务必保持）：配方中文名子串替换顺序（`bold 强调色`→`bold emphasis色`）、hex 回推失败保留原名、`_` 前缀键跳过、畸形配置静默容错、调试表示恒为 ANSI 原文。
4. 只依赖标准库（Windows 平台细节保留）+ contracts（如需）。
5. 中文 docstring。

## 测试要求

1. 覆盖 spec 每个 Scenario（映射表）。
2. 快照对照：若 `v2/tests/baseline/data/` 有配方解析等基准，编写对照测试；未有则跳过。
3. 颜色测试注意隔离：构造独立 Console/DisplayState 实例测试，不依赖全局态。

## 边界条款

- 只创建本积木文件与测试；不改其他文件
- 不运行 narnat；不执行 git 写操作

## 验收标准（可计算）

1. `python -m pytest tests/unit/test_output.py -q` 通过（cwd=v2）
2. `python tests/check_layering.py` 对 output 无违规（模块级注册表如不可避免，须加入 allowlist 并注明理由——优先不用）
3. spec Scenario 映射表齐备
4. 抽查：`bold 强调色` 怪癖与 R6 报告一致（报告给证据）

## 失败报告格式

①已尝试方案；②报错原文；③怀疑原因。「确认失败」是合法终点。
