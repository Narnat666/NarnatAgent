# T3.1 实施任务：compression 积木（上下文压缩）

## 任务目标

Stage 2：在 `v2/narnat_agent/` 实现 `compression` 积木（触发判定、切点选择、摘要编排、重建会话、溢出恢复、手动压缩）。

- **行为金标准**：`specs/compression/spec.md`（10 Requirement）
- **结构金标准**：`design.md`（D1/D6/D7）；依赖 `messages`（T2.4）与 `llm`（T2.5）积木 + `contracts`
- **现状参照**：`narnat_agent/core/compressor.py`、`compression_coordinator.py`、`context.py` + `docs/recast/reports/R1_report_core_dialog.md`

## 交付物

- `v2/narnat_agent/compression/__init__.py`、`compressor.py`（切点+重建+估算）、`coordinator.py`（触发/编排/恢复）、`context.py`（占比跟踪——归属本积木）
- `v2/tests/unit/test_compression.py`

## 实施要求

1. 对齐 spec 全部行为：占比触发（告警一次/压缩先于请求）、摘要请求（全历史+指令、no_tools、超限归因 overflow）、切点选择（保留尾部预算、平衡切割不拆 tool 配对）、重建（system+摘要+尾部、防连续 user 的合并/剔除规则）、结果归因（empty/interrupted/llm_error/empty_summary/overflow；失败不改动历史）、溢出恢复（原地重发、每次运行一次）、手动压缩（/compact、Esc 取消）、token 估算口径（系数）。
2. 结构改进：`ContextManager` 的转发层（compression_coordinator 全部转发调用）合并；回调式接口（on_interrupt/on_llm_error）改为返回值 + 结果对象承载（以 spec 的文案与行为为准）。
3. 无模块级可变状态；无私有互摸；依赖皆构造注入。
4. 中文 docstring。

## 测试要求

1. spec Scenario 全覆盖（映射表）。
2. 重点：切点选择矩阵（与 `v2/tests/baseline/data/compressor.json` 对照）、防连续 user 三分支、压缩结果归因、占比计算边界（窗口 ≤0、0/负值）。
3. 摘要请求/重建用 fake LLM 注入测试。

## 验收标准

1. `python -m pytest tests/unit/test_compression.py -q` 通过（cwd=v2）
2. `python tests/check_layering.py` 无违规
3. compressor 基准对照通过（用例级）
4. spec Scenario 映射表齐备

## 失败报告格式

①已尝试方案；②报错原文；③怀疑原因。「确认失败」是合法终点。
