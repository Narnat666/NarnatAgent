## 实施要求

1. **内循环状态机**（对齐 spec）：repair → 请求 → 事件消费（文本/工具/用量/完成/中断/重试通知）→ 工具执行 → 回传 → 下一轮；纯文本完成路径、错误路径、中断路径的出口与副作用（统计栏显示条件、`TurnOutcome` 返回——**用返回值替代现状 `_last_round_ok` 私有互摸**，含"本轮正常完成/中断/异常/空回复 + 已产出内容"）。
2. **工具调度**：计划优先拦截（文案）、三阶段分组（只读并行/写入按文件分组同文件串行/串行工具逐个）、结果按原始顺序、确认挂起（非 Windows：AWAIT 标记 → 结束流 → read_confirmation → 重执行或取消回传）、流取消时的杀进程广播（经 interrupt 订阅）。
3. **流中断重试**：无完成标记 → `restart_attempt()` + 通知 + 退避重试（上限=配置）、每轮重置预算、耗尽报错。
4. **溢出恢复**：`context_overflow` → 压缩后原地重发（每次运行一次）。
5. **收尾软提醒**：计划未勾选/后台任务运行中——各触发一次、注入文案精确、新任务复位（ReminderState）。
6. **目标模式**：GoalComplete 置位/复位、续跑注入文案、轮数上限收尾轮（force_final 语义）、`TurnOutcome` 驱动。
7. 依赖全部经构造注入；无私有互摸；无模块级可变状态；中文 docstring。
