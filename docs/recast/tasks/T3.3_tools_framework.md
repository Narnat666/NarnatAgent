# T3.3 实施任务：tools 框架（registry / signal / env）

## 任务目标

Stage 2：在 `v2/narnat_agent/` 实现 `tools` 积木的**框架层**（工具族未含在内，工具族另行任务）：注册表与执行入口、标签协议、运行时环境（ToolEnv 实现与 Trackers）。

- **行为金标准**：`specs/tools-file`、`specs/tools-shell` 的公共面（标签协议、参数错误文案、动态注册、执行入口判定顺序）+ `specs/mcp` 的注册面
- **契约**：`v2/narnat_agent/contracts/tool.py`（Tool/ToolResult/ToolEnv/Trackers 协议）
- **现状参照**：`narnat_agent/tools/registry.py`、`tools/exec_signal.py`、`tools/tool_context.py`、`tools/param_utils.py` + `docs/recast/reports/R5_report_tools_file_base.md`、`R3_report_tools_bash_bg.md`

## 交付物

- `v2/narnat_agent/tools/__init__.py`
- `v2/narnat_agent/tools/signal.py` — 标签协议（rc_line/error_line/tag_error/has_error/parse_rc/strip_tags/safe_cut_points，行为与现状及 spec 逐条一致）
- `v2/narnat_agent/tools/registry.py` — 注册表（静态注册 + 动态注册/注销；执行入口：参数兼容处理、错误包装文案、标签判定与剥离顺序）
- `v2/narnat_agent/tools/env.py` — ToolEnv 实现 + Trackers（PlanTracker/GoalState/ReminderState/DeleteGate/ReadFileTracker/ToolSettings）+ `AWAIT_CONFIRM` 常量引用
- `v2/tests/unit/test_tools_framework.py`

## 实施要求

1. **signal**：编解码与现状逐字一致（标签形态 `[?TAG]`、判定顺序"先判后剥"、`safe_cut_points` 语义）；模块级随机标签为进程级常量（允许模块级只写一次的常量，须在全大写或 allowlist 内）。
2. **registry**：执行入口的调用协议（参数注入 `_tool_context` 的现状机制由新 ToolEnv 替代——按 contracts 设计）；未知参数/缺参数的中文提示文案与现状一致；动态工具（MCP）注册/注销语义（重名跳过、按名去重）；`get_tool_definitions` 的过滤规则（GoalComplete 动态注入）。
3. **env**：Trackers 逐个实现 contracts 协议；状态归主（各 tracker 单一属主）；`ToolEnv` 聚合。
4. 无跨模块私有访问（消灭 `_delete_confirmed` 等私有互摸——改 DeleteGate 显式 API）。
5. 中文 docstring。

## 测试要求

1. signal 全函数与 `v2/tests/baseline/data/exec_signal.json` 对照。
2. registry：注册/注销/重名/参数错误文案（`v2/tests/baseline/data/param_utils.json` 可对照的部分）。
3. Trackers：各状态 API 的行为与 spec 语义（复位/消费/触发一次）。

## 验收标准

1. `python -m pytest tests/unit/test_tools_framework.py -q` 通过（cwd=v2）
2. `python tests/check_layering.py` 无违规
3. signal 基准全用例对照通过
4. 契约实现完整性：contracts 每个 Protocol 均有实现（报告列出）
