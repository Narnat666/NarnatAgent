# E2 探索任务：ESC 打断"不丝滑"真机复现（黑盒端到端）

## 现象（用户报告原文，逐字引用）

> 我打开narnat程序，询问你好，然后立即按下`键和esc键，交替按，这个时候ui会一直显示思考中，无法打断，也没有输出，后续狂按esc也没有用
> 等待了一会，才显示打断了，即当用户想按esc打断的时候，先按错了一个键，后续又按esc就会出现这种问题
> 用户狂按esc，后续过了很久界面显示已打断

## 任务目标

在**真实终端**中复现上述操作序列，产出带时间戳的证据，并对照新旧实现判定影响范围（是重构引入还是历史存在）。

## 复现对象（两个版本都要测）

- **新实现**（当前工作树）：`cd /d D:\desktop\NarnatAgent && python main.py -d`（`-d` 开调试日志，`.narnat/logs/`）
- **旧实现**（重构前稳定版，git `7d075a2`）：建议用 `git archive` 导出到临时目录（只读操作，不写 git 状态）：
  ```cmd
  cd /d D:\desktop\NarnatAgent
  git archive --format=zip 7d075a2 -o "%TEMP%\narnat_old.zip"
  :: 解压到 %TEMP%\narnat_old\ 后在解压目录运行 python main.py -d
  ```
  （解压目录无 `.narnat` 配置时，用环境变量 `NARNAT_HOME=D:\desktop\NarnatAgent` 指到有密钥的配置；旧实现支持该变量）
- 注意：两个版本的 `.narnat/logs/` 日志会覆盖同名文件，实验时注意隔离或记录轮次。用不同版本时分别启动。

## 复现序列（每条独立实验、重复 ≥3 次；每条之间等进程完全退出）

1. **基线**：输入"你好"回车 → 立即（<0.2s）按 ESC 一次 → 记录 [是否打断、延迟]
2. **错键+单 ESC**：输入"你好"回车 → 立即按 `` ` `` 一次 → 按 ESC → 记录
3. **交错连按**：输入"你好"回车 → 立即交替按 `` ` `` 和 ESC 各 ≥5 轮 → 记录
4. **纯狂按**：输入"你好"回车 → 等 1 秒 → 狂按 ESC ×10 → 记录
5. **延迟对照**：输入"你好"回车 → 等 2 秒 → 按 ESC → 记录

> 关键：序列 2/3 的"立即"要尽量精确（毫秒级），这是复现窗口。推荐用**程序化注入**而不是人手（见下）。

## 观察手段（选择能拿到可靠证据的路径；推荐第一种）

- **控制台注入 + 读屏（无需焦点，推荐）**：
  1. 用 `start` 在新控制台窗口启动 narnat（拿到其 PID）
  2. 自己的进程 `AttachConsole(pid)` → `GetStdHandle(STD_INPUT_HANDLE)`
  3. `WriteConsoleInputW` 注入按键事件（KEY_EVENT 记录：VK 码 + Unicode 字符；可精确控制毫秒间隔；`` ` `` = 0xC0/VK_OEM_3、ESC = VK_ESCAPE）
  4. 读屏：同一控制台 `ReadConsoleOutputCharacterW`/`ReadConsoleOutputAttribute` 抓取屏幕文本（判定"思考中"/"已打断"/统计栏）
  5. 注意：AttachConsole 后自身进程的 stdin/stdout 会被接管，需谨慎（`FreeConsole` 恢复）；建议注入与读屏用独立小进程完成
- 备选：`SendInput` + 窗口焦点（用 `SetForegroundWindow`；注意别抢当前终端焦点导致实验互相干扰）
- 辅助：`-d` 日志时间戳与按键时刻对照
