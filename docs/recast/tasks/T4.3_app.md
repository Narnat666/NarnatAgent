- **现状参照**：`narnat_agent/assembly.py`、`core/agent.py`、`main.py` + `docs/recast/reports/R8_report_mcp_assembly.md`、`R1_report_core_dialog.md`

## 装配线索（各积木已交付，接线点已在报告中标明）

- 各积木构造签名与"装配侧待接线"说明：见 `docs/recast/reports/T3.6_remote_report.md` 及各 T*.log 报告尾部；权威来源为各积木 `__init__.py` 的导出面与构造函数签名（以代码为准）。
- 已知接线点（汇总，实施时以代码核实）：
  - `llm`：注入 `config.defaults` 的 thinking 解析函数（T2.5b 改必需注入）；
  - `tools`：TodoWrite 注入 Theme（output）；`register_plan_tools(..., background=<shell 后台管理器>)`；
  - `conversation`：ToolDispatcher(resolve_device=Terminal.resolve_dev_display, interrupt=InterruptBus, theme=Theme, console=Console, executor=app 持有的线程池)；ConversationLoop(ai_options=AIConfig, data_dir, background=BackgroundManager, compression=压缩协调器, ratio=占比)；

- 退出清理：线程池 shutdown、terminal/serial/background/MCP 清理、日志关闭（正常与异常路径都执行；headless 另保证哨兵行先输出）。

## 实施要求

1. **装配**（design D8）：构造顺序即依赖顺序；**禁止后置裸赋值**（现状 4 处后置接线全部以构造注入或显式 attach API 消解）；装配产物不含散落 lambda（必要时为有类型的小对象/绑定方法）。
2. **交互主循环**：读输入 → 命令分发（`/` 前缀，退出码语义）→ 自动保存等待 → 压缩检查 → 状态复位（GoalState/ReminderState/计划）→ 内循环 → 自动保存 → 占比更新与告警；命令分发经 ui 的命令路由（sessions 命令表）。
3. **headless**：任务注入 → 目标模式（`-g` 覆盖）→ 哨兵输出 `[NN_DONE] reason=… rounds=…`（reason 取值集与现状一致）→ 不读输入/不保存会话/不查余额；异常路径仍保证哨兵与清理。
4. **生命周期**：线程池关闭、终端/串口/后台/MCP 清理、日志关闭（正常与异常路径）。
5. **无私有互摸**：主循环不摸 `agent_loop._last_*`（用 TurnOutcome）、不摸 `dispatcher._executor`（线程池由 app 持有并关闭）、不摸 `session_mgr._goal_*`（用公开 API）。
6. 中文 docstring。

## 测试要求

1. spec Scenario 覆盖（映射表；含装配产物完整性——各组件存在且类型正确）。
2. 主循环/headless 用 fake 组件驱动（如 fake InteractionPort + 脚本化 TurnOutcome）测流程与哨兵。
3. 装配冒烟：装配成功且分层检查通过。

## 验收标准

1. `python -m pytest tests/unit/test_app.py -q` 通过（cwd=v2）
2. `python tests/check_layering.py` 全包通过
3. `cd v2 && python main.py -v` 输出 `narnat <版本>` 且退出码 0（不触发网络）
4. spec Scenario 映射表齐备
5. 后置补线清单与现状 4 处的消解证据（报告）
