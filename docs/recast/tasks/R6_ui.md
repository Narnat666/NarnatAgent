对每个源文件一节，含以下字段：

```markdown

**职责**：一句话。

**对外接口**（public 类/函数/方法，逐个列签名）：
- `签名`：用途一句话

**依赖**（本文件 import 了哪些内部模块，附行号）

**被依赖**（谁 import 本文件：用 grep 搜索模块名/类名，列出 import 方及行号）

**状态**：
- 模块级全局：名称（是否可变，读/写位置行号）
- 类变量：...
- 实例状态：关键属性清单

**行为要点**（编号；每条附行号；这是写规格的素材，要写"可观察行为"）：
1. ...

**边界/异常行为**（编号；附行号；空值/0/负数/超长/编码/平台分支/重试/回退等）：
1. ...

**补丁痕迹**（编号；附行号+证据；判据：跨层引用、可变全局、职责混杂、重复代码、脆弱边界、
吞异常、魔法值、历史包袱注释、死代码；每条标严重度 高/中/低）：
1. ...

- 可独立单测的部分（列函数名+原因）
```

特别关注（本组重点）：
- renderer.py 的**流式 Markdown 渲染**：增量解析、表格稳定渲染策略、代码块高亮与语言配色、宽度计算（CJK 双宽字符）、软换行/断行规则——这部分是"最难测但用户可见"的核心，行为要写细。
- output.py 的**颜色体系**：全局开关（plain/quiet）、Windows VT 启用、truecolor 检测、调色板解析（_parse_recipe）、apply_style 写入链路、DisplayState。
- ui_design.py 的 **UIInterface 类职责**：输入读取（prompt_toolkit）、命令分发、流式输出生命周期（create_stream/feed/finish/abort）、状态栏渲染。
- session_commands.py 的**命令注册表**与 Tab 补全机制。
- interrupt.py 的**Esc 中断链路**（键盘监听 → _interrupt_ctrl → 各类 abort 回调）——多线程时序，重点写清线程与信号路径。
- headless.py 的**纯文本输出模式**（受 set_plain/set_quiet_tools 影响）。
- ui/colors.py 的静态颜色常量与消费方。
