# T0.1 实施任务：快照基准提取（对旧实现生成行为基准）

## 任务目标

narnat agent 重构中（change `recast-v2`），需要为"行为等价"建立**可计算判据**：对旧实现（`narnat_agent/`，原位未动）运行一组确定性用例，把输出固化为基准数据；未来新实现跑同样用例、逐个比对。

你负责：创建基准提取工具并生成基准数据。

## 交付物

1. `v2/tests/baseline/cases.py` — 用例定义（纯数据：输入样例集合；与实现无耦合）
2. `v2/tests/baseline/extract_old.py` — 对**旧实现**执行用例并产出基准：
   - 运行方式：`cd /d D:\desktop\NarnatAgent && python v2/tests/baseline/extract_old.py`
   - 产出：`v2/tests/baseline/data/*.json`（每类用例一个文件，UTF-8、indent=2、ensure_ascii=False）
   - 必须**幂等**：连续运行两次，输出逐字节一致（随机性内容须结构化处理，见下）
3. `v2/tests/baseline/README.md` — 说明：如何生成基准、如何（未来）对新实现比对、每类用例的行为说明

## 用例覆盖清单（以纯函数/可安全调用的行为面为准）

| # | 模块（旧包路径） | 用例输入 | 基准输出 |
|---|---|---|---|
| 1 | config.loader：`_coerce`/`_parse_token_amount`/`_parse_model_config`/`_parse_pricing`/`_parse_project_skill_roots`/`parse_mcp_server`/`_strip_subagent_hidden`/`_build_system_prompt`/`_build_ai_config`/`_build_ui_config` | 边界值矩阵（None/空串/非法/负数/布尔/字符串数字/各种别名键） | 解析结果（扁平 JSON） |
| 2 | config.session_store：`_safe_filename`/`format_session_tree`/`format_session_summary`/`format_session_list` | 名称样例集；构造的会话树数据结构 | 返回值/格式化文本 |
| 3 | tools.exec_signal：`rc_line`/`error_line`/`tag_error`/`has_error`/`parse_rc`/`strip_tags`/`safe_cut_points` | 样例命令/输出文本/截断边界 | **随机标签模式化**后的结构（如把随机 tag 替换为 `"<TAG>"`；同时记录 `has_tag` 布尔） |
| 4 | config.defaults：`resolve_thinking_params`/`resolve_thinking_passback` | 协议(anthropic/openai)×模型前缀(deepseek/glm/kimi/mimo/qwen/gpt/claude/未知)×强度(high/max/low/空)×回传开关 的矩阵 | 参数 dict/回传格式 |
| 5 | ui.renderer：宽度计算/行渲染纯函数（`_display_width` 等；先 `output.apply_style({})` 固定默认色）| 样例行集（中英混排、emoji、ANSI、长行） | 渲染文本/宽度数值 |
| 6 | output：配方解析（如 `_parse_recipe`/色名解析） | 配方样例（`bold 蓝`/`italic dim 次文字`/hex/无效组合） | 解析结果 |
| 7 | core.billing：`get_pricing`/`cost_breakdown`/`calculate_cost` | 模型×用量矩阵 | 费用数值 |
| 8 | tools.token_estimate：`estimate_text_tokens`（若存在）/core.compressor 的估算函数 | 文本样例集（中文/英文/代码/混排） | 估算数值 |
| 9 | core.message_list：构造→append 序列→（repair 场景） | 消息操作脚本序列 | 操作后消息列表 JSON |
| 10 | core.compressor：`select_cut_index`/`_cut_balanced` | 消息序列×retain_tokens 矩阵 | 切点索引 |
| 11 | tools.param_utils 及 registry 参数错误路径（如 `_friendly_type_error`） | 非法参数样例 | 错误文案 |

要求：
- 只调用**读取/计算类**接口；禁止调用任何会启动进程、连网、写用户数据、读取真实用户配置的路径（config 用例全部用构造 dict，不经 `load_config` 的磁盘路径）
- 若某模块导入有副作用（如 import 时构建正则/读环境），允许，但不得触发写操作
- 输出必须**确定性**：涉及随机数（标签）、时间、路径的，做模式化替换并在 README 注明
- 用例输入集中在 `cases.py`，提取器只做"输入→调用→序列化"

## 边界条款

- 只创建 `v2/tests/baseline/` 下的文件；不改任何其他文件（尤其不动 `narnat_agent/` 旧包）
- 不运行 narnat / main.py；不执行 git 写操作
- 报告内如有"无法提取"的用例，列明原因（如依赖终端/网络），不强行提取

## 验收标准（可计算）

1. `cd /d D:\desktop\NarnatAgent && python v2/tests/baseline/extract_old.py` 退出码 0
2. 连续运行两次，`data/` 下文件逐字节一致（用 `certutil -hashfile` 或 python hash 对比）
3. `data/` 下 JSON 文件数量 ≥ 8，覆盖清单 11 项中可提取的项（清单逐项在 README 打勾）
4. 任取 3 个基准值，人工核对与旧实现直接调用一致（在报告中给出核对命令与结果）
5. README 含"如何比对新实现"一节（步骤化）
