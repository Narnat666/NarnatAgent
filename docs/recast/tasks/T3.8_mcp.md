# T3.8 实施任务：mcp 积木（MCP 客户端与管理器）

## 任务目标

Stage 2：在 `v2/narnat_agent/mcp/` 实现 MCP 集成（stdio 客户端、连接管理、工具热注册，含 MCP 工具）。

- **行为金标准**：`specs/mcp/spec.md`（11 Requirement / 45 场景）
- **契约**：`contracts/tool.py`（ToolCatalog 端口用于工具热注册）+ `tools/signal.py`（错误文案）
- **现状参照**：`narnat_agent/mcp/__init__.py`（343）、`mcp/client.py`（342）、`tools/mcp_tool/` + `docs/recast/reports/R8_report_mcp_assembly.md`

## 交付物

- `v2/narnat_agent/mcp/__init__.py`、`client.py`（JSON-RPC stdio）、`manager.py`（连接管理）
- `v2/narnat_agent/tools/mcp_tool.py`（MCP 工具 connect/disconnect，注册进 tools 族——放 tools 或 mcp 均可，按依赖方向定：工具实现依赖 manager，故放 mcp 内部导出）
- `v2/tests/unit/test_mcp.py`

## 实施要求

1. 对齐 spec：工具参数契约、连接流程（子进程启动/握手/列举/分页）、命名规则（前缀/非法字符/64 截断+哈希/重名/白黑名单）、调用协议与结果格式化、断开语义（注销/终止/`all`）、自动重连（不自动重跑）、进程生命周期（独立进程组/并发上限 8/幂等清理）、失败不阻塞文案。
2. **结构改进**：`mcp → tools.registry` 的函数内延迟导入改为经 `ToolCatalog` 端口注入（design D8）；`connect()` 70 行 6 职责拆分；atexit 注册竞态修复（以 spec 语义为准）。
3. 依赖方向：mcp（L2）不 import tools（L2）——工具实现按 contracts 的 Tool 协议 + signal 文案；工具注册经端口。
4. 中文 docstring。

## 测试要求

1. spec Scenario 全覆盖（映射表）。
2. 命名规则矩阵（非法字符/超长/重名/空名哈希兜底）全测——纯函数。
3. 客户端协议用 fake 子进程（如 `python -c` 的 echo JSON-RPC 服务器脚本）测试握手/调用/重连路径；或注入 fake 传输。

## 验收标准

1. `python -m pytest tests/unit/test_mcp.py -q` 通过（cwd=v2）
2. `python tests/check_layering.py` 对 mcp 无违规
3. spec Scenario 映射表齐备
4. 命名规则与 R8 报告逐条一致（报告证据）
